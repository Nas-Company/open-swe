## Design Context

### Users

Open SWE is used by internal engineers, product operators, and other trusted teammates to delegate technical work, follow agent progress, review changes, and collect final deliverables. They need fast access to results and clear evidence that an artifact belongs to the current task.

### Brand Personality

Precise, calm, and trustworthy. The interface should feel like a capable engineering workspace: compact enough for frequent use, clear about system state, and free of decorative noise.

### Aesthetic Direction

Use the existing refined utilitarian visual language: neutral surfaces, restrained blue accents, compact typography, and the current light/dark theme tokens. Chat remains the primary surface; secondary workspace capabilities use progressive disclosure. Avoid marketing-style layouts, oversized cards, ornamental gradients, and visual effects that compete with task content.

### Design Principles

1. Make provenance and state obvious: show which task produced a file, when it was published, its type, and whether an action is pending or failed.
2. Keep the conversation primary: generated files live in the existing workspace panel and become prominent only when available.
3. Prefer plain, action-oriented language such as `Files`, `Download`, and `Retry`.
4. Preserve accessibility and responsive behavior: keyboard-operable tabs, descriptive labels, readable status messages, and a complete mobile experience.
5. Treat generated artifacts as untrusted content: download them as attachments and never execute HTML on the dashboard origin.
